# Train Model Windows UI review — October 21, 2026

## Environment and scope

Native UI verification uses the signed-in Windows 11 desktop in the `win11`
VM (`kevin-vm`, build 26300.9457), with Python 3.14.4, PySide6/Qt 6.11.2,
and PyInstaller 6.22.2. The inspected source is copied into an isolated
`C:\Users\k\to-build\review-20261021` folder. No branch is changed.

The initial Linux run is not evidence of Windows scaling correctness. The
Windows checks below operate actual QML controls through mouse and keyboard
events, run the two real launchers in separate processes, and use native
Windows border drags. Display scale is changed through Windows Settings,
not a Qt scale-factor override. Temporary display changes are restored.

## Fixes

- Startup frames exceeded the 1280×800 desktop's 1280×752 work area. Both
  launchers originally opened with a 1250×781 client and a 1250×812 Qt frame,
  hiding the bottom controls behind the taskbar. Shared startup sizing now
  accounts for the native frame and work area. Both corrected clients are
  1154×721 with a 1154×752 frame on that display.
- At 125% display scaling, an inward drag at minimum size could grow the
  window by one physical pixel. The lock now preserves the existing native
  minimum rectangle, including either rounding of the fractional height.
  Outward resizing remains enabled.
- Both standalone launchers omitted the shared application icon. The shared
  bootstrap installs it, and the Windows packaging recipe includes the PNG.
- The disconnected test UI incorrectly displayed an E-brake badge. Connection
  state stays in its mode badge; the brake badge now follows the actual brake.

The sizing changes are in shared `ui/aspect_lock.py`, so other module
windows using it inherit them. The native UI rehearsal here covers Train
Model and Train Model Test UI; it does not claim a CTC Office UI review.

## Regression results

The final Windows suite passes **878 tests**, with **13 existing skips**, in
44.55 s. This includes 24 new minimum-size regression cases covering all
eight handles, both fractional-height roundings, and outward resizing.
Twelve skips concern the inactive Train Model door interlock; one is the
obsolete stub implementation. No new tests are skipped to obtain this result.

Run from `TrainModel` with the Windows project virtual environment:

```powershell
$env:QT_QPA_PLATFORM = 'offscreen'
$env:QT_QPA_FONTDIR = 'C:\Windows\Fonts'
python -m pytest -q -rs
```

`QT_QPA_FONTDIR` supplies real Windows fonts to Qt's offscreen plugin. Native
desktop tests use the Windows font system and the `windows` platform plugin.

The opt-in native startup regression is:

```powershell
python TrainModel\tests\windows_startup_check.py --shots startup-shots
```

Run it from the repository root in the signed-in Windows desktop session,
with `QT_QPA_PLATFORM` unset. It checks both actual launchers, the work-area
containment, aspect ratio, and icon, using private socket names.

## End-to-end rehearsal

The native two-process rehearsal exercises:

- Starting the test UI before the model and connecting without a tick.
- Sending default inputs; lights and the next-station beacon reaching the model.
- Entering power, running at 10×, movement, position, clock agreement, and Hold.
- Engine, service-brake, and signal-pickup failures and recovery while paused.
- Passenger emergency-brake confirmation, immediate propagation, and test-UI release.
- Rejected input leaving clock, latch, and model state unchanged, then correction.
- Announcement display and dismissal.
- Adding, selecting, and removing trains across both windows.
- Opening a door, one-shot boarding, a 45-second dwell, and departure.
- Reset, model closure, automatic reconnection, and a fresh accepted tick.

## Limits

This is Train Model and its removable test utility, not full production Track
Model integration or a hardware test. The VM has one virtual monitor; moving
between physical monitors with different DPI is not verified. Existing
test-utility and extreme-input limitations remain in [bugs.md](bugs.md),
including downhill dwell with service-brake failure, rollback control, and
very long identifiers. Previously accepted exceptions are not changed here.

## Native scaling matrix

Both windows pass 24 native checks at each real Windows scale setting:

| Windows scale | Native DPI | Model | Test UI |
| --- | --- | --- | --- |
| 100% | 96 | 24 passed | 24 passed |
| 125% | 120 | 24 passed | 24 passed |
| 150% | 144 | 24 passed | 24 passed |
| 200% | 192 | 24 passed | 24 passed |

The **192 checks** cover five canvas sizes/shapes, eight outward border/corner
drags, eight inward minimum-size drags, maximize, fullscreen, and snap-left.
Client rectangles are sampled during real mouse drags, not just at the end.
Minimum-size drags must leave all four frame coordinates unchanged. Outward
drags must resize and preserve the opposite edge. Canvas scaling stays uniform
and centered in every window state.

The DPI run temporarily uses a supported 3840×2160 VM display. Requested sizes
are bounded to the current logical work area at high DPI; measurements record
the actual client sizes. Native DPI and Qt device-pixel ratio are both recorded.
The original 1280×800 resolution and 100% scaling are restored afterward.

The final end-to-end rehearsal passes with zero Qt/QML warnings in both
processes. Its results and the DPI measurement JSON are saved in the companion
review evidence folder, alongside screenshots and the driving scripts.
