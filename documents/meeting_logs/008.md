## Meeting Notes

Kevin walked the team through the new `truth` branch and how shards flow into it,
the team cleared a module header naming collision between two open PRs, settled
two outstanding unit questions, and set expectations for the week leading into
the iteration two presentations.

### Module Header Naming Conflict

Braden's and Kevin's branches both define a module header component, but they are
not interchangeable — Braden's carries the wayside number and the loaded database,
which Kevin's does not. Since Kevin already has a PR open, he will leave a comment
on it asking for Braden's header to be renamed and will rename his own as well, so
the two can coexist rather than one silently overwriting the other.

Braden also confirmed his implementation keeps genuinely shared components in the
shared kit while module-specific ones stay separate; Kevin agreed that is the
right split. Kevin's aspect lock lives in `aspectlock.py` under the UI folder.

### `truth` Branch

Kevin demonstrated the `truth` branch, which holds only hard facts — conventions,
unit definitions, templates, and the like — so that every agent references the same
ground truth regardless of who is developing or where. Every agent pulls the branch
at the start of a session. Templates exist for each entry type so agents write in a
consistent shape, and the agent is currently prompted to check in every five
entries, though that cadence may loosen now that the branch is no longer empty.

The branch deliberately excludes mutable state. Statuses, what is stubbed, and
anything else that changes during development stay in each member's module folder.

Kevin called the conventions folder the single most important folder on the branch:
it defines the toolchain, frontend and backend units, naming conventions, how
things are identified, and where things live. Landis asked where per-module
requirements belong — what his module must do and what it communicates with — and
Kevin pointed to the module shards, whose templates describe what to put in them.

Kevin wants to insert a skill between Claude and the agent to force an `agents.md`
check on every run rather than relying on the agent to remember.

### Shard Handling in Pull Requests

Braden's open PR contains shards his agent left in the inbox. Shards on a feature
branch merge into `truth`, not into `development`, so they should be deleted before
the PR is opened; PR review is the second gate if one slips through. Braden noted
the expensive part was the agent tracing reasoning across branches to find the
files, inbox, and formatting — five to ten minutes per submission — so he had it
write memory files to make the process repeatable.

### Unit Decisions

Distance is stored in meters on the backend. Ivan raised that a train can stop
anywhere within a block rather than exactly at its edge, so position has to be a
distance rather than a block index. Kevin's preference is the simpler rule: instead
of relying on the train model's calculated offset into a block, treat reaching the
target block as the stop condition and go no further. Harry asked whether anything
would require stopping halfway through a block; Kevin knows of nothing beyond
emergency braking, and Harry agreed the simpler rule makes sense.

Gradient was settled as degrees.
