## 1. Facts that shape every diagram

- The Train Model is **physics only** (D009). It applies the commands it gets.
  It does not regulate speed, enforce the 70 km/h maximum, cut traction under
  braking, or enforce a door interlock. All of that belongs to the Train
  Controller.
- It is stepped from outside with `step(dt, inputs) -> outputs`, and dt is
  fixed (D006). The shared `SystemClock` ticks every 0.1 s by default, at 1x
  or 10x (D017). Speed changes how often ticks happen, never dt.
- The integrated module has one process holding a fleet and its window. A
  separate removable developer utility exists for standalone use (D010).
- Failures (engine, signal pickup, brake) are injected **only** from the Train
  Model window, by "Murphy". They are **not** sent to the Train Controller.
  The `failure-status` signal is withdrawn.
- The passenger emergency brake is pulled from the Train Model window and
  latches. The window has no release. The latch clears when the Train
  Controller's `emergency_brake` goes from true to false.

## 4. Sequence diagram: integrated tick

Title: **Train Model: one integrated harness tick**.

Lifelines: harness/SystemClock (external process), ModuleLink, TrainModelProcess,
TrainModelFleet, selected TrainModelState, physics TrainModel, and Main.qml.
Keep the clock outside the Train Model process; one fleet owns all per-train states.

1. Harness sends STEP with tick number, fixed dt, unwrapped end-of-tick `sim_time_s`,
   and roster-keyed inputs from direct producer-to-consumer edge mappings.
2. ModuleLink invokes `TrainModelProcess.step(tick, dt, sim_time_s, inputs)` on the
   owning Qt thread. Reject a malformed top-level trains object without stepping.
3. The adapter follows roster additions/removals and fans supplied time to the fleet
   for display, including the idle empty-fleet view. Identity/line are roster metadata.
4. For each train, establish its epoch once as first supplied timestamp minus dt,
   decode module-owned inputs, and validate before physics mutation.
5. `alt [valid train]`: state calls model.step. Validate; clear passenger latch if
   release is commanded; follow doors; draw disembark/board when eligible; detect
   polarity change; integrate exact constant-force and midpoint power-limited
   segments totaling dt; update temperature and accepted elapsed time; build outputs.
   `else [invalid train]`: preserve physics/output/random state and record rejection;
   other trains still advance. Display may still show current harness time.
6. State refreshes selected-train bindings. QML reads independent brake states,
   front offset, next station/platform, and fleet identity/line; no arrival field
   appears in the intended window.
7. `opt [tick % 15 == 0]`: compare epoch plus accepted elapsed model time against
   supplied unwrapped time for every train, including rejected trains. Use absolute
   tolerance 1e-6 s; publish selected-train drift diagnostics. Never reset epoch or
   accepted elapsed physics time to hide a mismatch.
8. Adapter returns per-train outputs and rejection reasons to the harness. Harness
   routes producer outputs once for consumers’ next-tick input snapshot.

A passenger pull or Murphy action changes local state between steps. Its physical
response occurs on a later accepted step and cross-module routing occurs through
harness outputs. Controller one-shot release clears the passenger latch while a
held controller emergency command remains active. The standalone developer link
and its older 30-tick check are development references, excluded from this diagram.

with READY/STEP/OUTPUTS/QUIT lifecycle messages and request/tick identifiers.

`common/interfaces.py`. Closing a module window hides it; only the harness ends
